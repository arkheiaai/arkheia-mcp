# Testing
#
# THIS is the file that declares the repo's test/tooling environment. The other
# three requirements files here do not, and the "code under X/ is governed by
# X/requirements.txt" reflex is wrong three times out of four in this repo:
#   * mcp_server/requirements.txt  — runtime only (mcp/httpx/pydantic/anyio); it
#     declares no runner at all, and mcp_server/Dockerfile installs the ROOT file.
#   * npm-wrapper/python/requirements.txt — what a CUSTOMER's venv installs to run
#     the published bundle. Test tooling there would ship pytest to every `npx`
#     user.
#   * proxy/requirements.txt — the one case where it does hold, and it carries its
#     own pytest/pytest-asyncio.
# Everything else — `tools/*` (no requirements file of its own), `scripts/*`,
# `tests/*`, and every CI job, all of which install THIS file first — lands here.
#
# pytest-timeout and respx were installed AD HOC by the workflows and declared in
# NO requirements file, so CI green did not mean the declared manifest could run
# the suite. Both proven red 2026-07-26 against a venv built from this file alone:
#   `pytest tests --timeout=120` -> "unrecognized arguments: --timeout=120"
#   `pytest tests/test_detection_adapter.py` -> 5 ERRORs (respx_mock fixture absent)
# `--timeout=` is passed by FOUR consumers and none of them declared it:
# unit-tests.yml (--timeout=120), smoke-test.yml (--timeout=60),
# tools/mutate_f18_integrity_manifest.py (--timeout=180), and
# tools/mutate_f1_tool_gate.py. Both workflows carried a bare `pip install
# pytest-timeout` line, so CI was green while a fresh install of our own declared
# environment could not run the harness at all -- an evidence-reproducibility
# defect rather than a runtime one, since the proof that mutants are killed
# cannot be re-derived from what we declare. The ad-hoc pip lines are the
# masking, exactly as they were for `cryptography` above.
